#+title: closure — capability roadmap
#+todo: TODO(t) WIP(w) | DONE(d) DROP(x)

Working agreement for autonomous sessions: work top-down, pick the
highest =TODO=, split it into small TDD cycles, flip it to =DONE= in the
same commit that finishes it. Every item must pass the test "after this
the user can ___, which they could not before" — if the blank only
names a new method, the item does not belong here. Statistics/alias
accessor methods on closure-org/store/input are done; add no more
unless a feature in the same cycle calls one. Architecture contract
lives in [[file:docs/spec.md][spec.md]] (invariants I1–I10) and [[file:docs/phases.md][phases.md]] (milestones); this
file is the fine-grained, capability-level queue between them. Blocked
on a design decision? Record it under [[*Decisions][Decisions]], pick the most
reversible option, keep moving.

* DONE Edges: make the mocked surfaces real [4/4]
The kernel (org/core/store/query/undo/input) is deep + tested; the
real-world *edges* are trait+mock+deferred. These four are the highest
TODO because each is a spec promise the code does not yet keep, or a
security hole. Each carries a spec-revision note (I7/I8 rule: the spec
is revised in the SAME commit that closes the gap — no silent drift).
** DONE C1 Eval sandbox — close the RCE hole [3/3]
Today =closure-eval/src/lib.rs:74,97= pipes code blocks to =/bin/sh=
and =python3= with no isolation. A Babel block in a synced/P2P'd org
file is remote code execution on pull. spec.md:156 already claims
"sandboxed evaluator" — the code does not honour it. This is the most
urgent gap (security > features).
After this the user can: pull/sync an untrusted vault without a
malicious =#+BEGIN_SRC= block executing arbitrary local commands.
*** DONE C1a Default-deny eval: code blocks do NOT execute unless the
vault's =config.org= opts in via a typed =eval_trust= allowlist
(closure-config, validated at load I9; empty/unreadable => deny). Pure
gate =closure_eval::eval_allowed= (canonicalises lang+alias) +
=canonical_language=; =Vault::eval_block= and =closure eval= both check
it before spawning, returning =VaultError::EvalBlocked= / a "blocked"
notice — a pulled/synced vault runs no code without explicit local
trust. Tests (RED->green): closure-eval policy (empty denies, alias
both sides, case-insensitive — 5); closure-config (=eval_trust= parses,
defaults empty — 2); closure-store babel (default-deny runs nothing +
untrusted-language blocked, trusting tests opt in via config.org — 14);
closure-cli (eval default-deny vs trusted — 2). Spec revised
(spec.md Layer 3) + Decision below, same commit.
*** DONE C1b Resource bounds on the interpreter backends: new
=closure_eval::Bounds= (wall-clock deadline 10s + per-stream output cap
10 MiB) + =run_bounded= — child spawned in its own process group
(unix), stdout/stderr drained on threads with a byte cap; a runaway is
killed at the deadline (=EvalError::Timeout=), a flood is killed at the
cap with the output truncated (never buffered whole). =Backend=
exposes =eval_bounded= (overridden by all four interpreter backends);
=Vault::eval_block= and =closure eval= run under =Bounds::default()=.
Hermetic tests (RED->green, =/bin/sh=): infinite loop killed <5s;
=head -c 50MB /dev/zero= truncated to a 4 KiB cap without hanging;
normal small output unchanged. Spec revised (spec.md Layer 3) same
commit. Note: true forkbomb containment (group-kill of descendants)
needs a negative-pid signal — =#![forbid(unsafe_code)]= rules out the
libc call; the process-group isolation is in place and C1c's wasm
sandbox is the real containment tier. Recorded, not faked.
*** DONE C1c wasm sandbox exec tier: =closure_eval::WasmBackend= (opt-in
=wasmtime= feature) runs a =wasm= block (WAT text or binary) under
wasmtime with NO host imports and a finite fuel budget — a module

Decision below; =just check= green with the feature OFF. Improves on
the original plan: fuel-bounding means even the sandbox tier can't hang.

** DONE C3 Sync authentication + encryption [2/2]
=closure-sync= ships =SyncMessage= over plaintext TCP with no identity,
auth, or encryption (grep: no tls/crypto/auth in the crate). P2P collab
on an untrusted network = anyone reads/injects replica deltas. The
vision's P2P pillar has no security model.
After this the user can: sync over a hostile network without a peer
forging or eavesdropping on edits.
*** DONE C3a Peer identity + frame authentication: each peer holds an
ed25519 keypair (=SigningKey=/=VerifyingKey=, pure-Rust =ed25519-dalek=,
hermetic — I10 intact). =SyncMessage::to_signed_bytes= signs the version
byte + encoded replica (=magic | 2 | pubkey | sig | payload=);
=from_signed_bytes(bytes, trusted)= verifies the signature against the
embedded key (catches tampering, incl. version downgrade) and, when
=trusted= is non-empty, requires the signer be a pinned peer (rejects a
forged/unknown signer) — all BEFORE the message reaches =apply_message=.
Tests (RED->green, hermetic): signed frame verifies + converges into a
peer; a tampered payload byte fails verification; a valid signature from
an untrusted key is rejected; empty trust = integrity-only. Spec revised
(spec.md Layer 3 closure-sync) + Decision below, same commit.
*** DONE C3b Transport encryption: =NoiseChannel= — a Noise NN channel
(pure-Rust =snow=: x25519 + ChaCha20-Poly1305 + BLAKE2s, no async
runtime, hermetic) with =encrypt=/=decrypt= + socket handshake
(=handshake_initiator=/=handshake_responder=). =TcpSyncTransport=
gained =connect_and_sync_secure=/=serve_once_secure=: Noise-handshake
the socket, then exchange the C3a-**signed** frames over the
**encrypted** channel (confidentiality from Noise + authenticity from
the inner signatures), verified against the trusted set before
=apply_message=. Same =SyncMessage= framing => iroh/QUIC stays a
drop-in. Tests (RED->green, hermetic): wire bytes != plaintext (no
=CLSY= magic, no title leak); encrypted round-trip decrypts +
converges; tampered ciphertext rejected by the AEAD tag; full secure
TCP round-trip over =127.0.0.1= converges (2 blocks both ends). Spec
revised (spec.md Layer 3 closure-sync) + Decision below, same commit.
** DONE C4 Scale: prove the kernel on a real-world vault [2/2]
Perf guards ran only on a 1-2k-headline synthetic vault. C4 proves the
kernel on a 50k-headline vault — and it already scales linearly.
The user can now open + search + backlink-resolve + incrementally
reload a 50k-headline vault with no perceptible lag.
*** DONE C4a Large-vault fixture + budget tests: =closure-store=
=tests/scale.rs= builds a real 50k-headline vault on disk (500 files x
100 + a hub) and =Instant=-times the hot paths against generous budgets
(no criterion). Measured (debug, dev machine): =Vault::open= ~0.6s,
=closure_query::fuzzy_filter= over 50k titles ~0.4s, =backlinks_of=
~7µs (O(1) index), =reload_incremental= on an unchanged vault ~0.07s
with 0 reparses. (closure-query added as a test-only dev-dep — cargo
permits the dev-dep back-edge.) All linear; budgets catch an O(n²)
regression (seconds+) without micro-tuning machine speed.
*** DONE C4b Fix the worst offender found in C4a: none. C4a found no
quadratic / rescan / O(n) hot path — load, fuzzy, backlink, and
incremental reload are already linear/constant at 50k (the content-hash
index cache, the backlink HashMap, and span-preserving parse all hold
up). Nothing to fix; the budget test is the standing regression guard.
Recorded honestly rather than inventing a change.

* Decisions
Open questions land here as subheadings: context, options considered,
the reversible default taken, date.
** DECISION (2026-06-20) Flutter shell stays external (X1d)
Context: X1d reopened a Flutter shell. The Flutter SDK (Dart toolchain +
=flutter= CLI) is not hermetically nix-packaged like the pure-Rust +
pkg-config GUI stacks (gtk4/webkit/Qt all provisioned cleanly for
X1a-c); vendoring it would break I10's reproducible build. Options: (a)
force a Dart toolchain into the flake (non-reproducible, fragile); (b)
keep Flutter as an external project that consumes closure over a stable
surface. Taken (b), documented in =docs/flutter-shell.md=: either a
=WebView= over =closure serve= / =export html= (Option A, no FFI) or
=flutter_rust_bridge= over a =cdylib= wrapper of =closure-shell-core=
(Option B). Both keep the Rust side hermetic + route mutations through
the registry (I8) / consume a stable surface (I7); only the Dart build
is external. Reversible: a feature-gated crate can replace this if a
hermetic Flutter/Dart nix story matures. Unlike X1a-c (real building
feature-gated crates), Flutter genuinely cannot satisfy I10 in-tree —
recorded per the binding rule rather than faked.
** DECISION (2026-06-20) Tauri shell = wry/tao webview, not full Tauri (X1a)
Context: X1a asked for a Tauri shell hosting the web UI. Full Tauri v2
needs tauri-cli, a bundled JS frontend project, and config/build
ceremony — none of which fits a single hermetic Rust workspace crate
(node/tauri-cli are not in the dev shell). Options: (a) vendor a full
Tauri app (node frontend + cli bundling, non-hermetic packaging);
(b) use =wry= + =tao= directly — the exact webview + windowing libraries
Tauri itself is built on — and load the closure web shell's already
self-contained =export_html= page. Taken (b): it delivers the native-
webview capability (a desktop window showing the vault UI) as a thin
Rust crate over the tested =export_html=, with no JS toolchain. The
heavy native libs (wry pulls webkitgtk + gtk3) sit in a dedicated
=devShells.webview= so the default build + =just check= stay light and
hermetic (I10); the feature is default-OFF. Window launch is display-
bound (verified by build + manual run, like egui/gpui). Reversible: a
full Tauri-cli packaging project can wrap the same web shell later
without touching the workspace.
** DECISION (2026-06-19) Transport encryption: Noise NN via snow (C3b)
Context: C3b needs an encrypted channel over the std-TCP transport
(2026-06-17 P2P Decision keeps TCP, no tokio/rustls). Options: (a)
rustls/TLS — pulls tokio + a big async tree, fights I10; (b) =snow=
(Noise) — pure-Rust, default-resolver (x25519/ChaCha20-Poly1305/
BLAKE2s), no async runtime, no C. Taken (b). Handshake pattern: NN
(ephemeral-only, no static keys) — confidentiality only, because peer
*authenticity* is already provided by the C3a ed25519 frame signatures
carried inside the channel; layering the two keeps each concern simple
and avoids a static-key-distribution story for the handshake. Trade-off:
NN alone is MITM-able, but the signed inner frames make a MITM unable
to forge a trusted peer's edits (it can drop/replay, not forge). One
Noise transport message caps at 64 KiB, so a very large replica would
need chunking — noted; current frames are far smaller. Reversible: swap
NN for XX (mutual static auth) or move to iroh/QUIC behind the same
=SyncMessage= framing.
** DECISION (2026-06-19) Sync auth uses ed25519-dalek (first crypto dep)
Context: C3a needs frame signing; the workspace had no crypto dep. The
P2P Decision (2026-06-17) keeps sync on std TCP to avoid tokio/rustls

** DECISION (2026-06-19) Eval is default-deny via typed eval_trust (C1a)
Context: =closure-eval= spawned =/bin/sh=/=python3= for any code block
with no gate; spec.md claimed "sandboxed evaluator" but nothing
enforced it. A Babel block in a pulled/synced vault was local RCE.
Options: (a) sandbox first (seccomp/wasm) before allowing any exec;
(b) a typed trust allowlist that defaults to deny, with sandbox tiers
(C1b/C1c) hardening the trusted path afterwards. Taken (b): smallest
change that closes the hole now and is composable — =eval_trust= is a
typed config key (I9), the gate is a pure function reused by both the
Vault and CLI exec paths, and empty/unreadable config denies. Trade-off:
a trusted shell/python block still runs unsandboxed until C1b/C1c land;
that is now an explicit, opted-in risk rather than the silent default.
Reversible: C1c adds a wasm-only sandboxed tier as the safe default for
portable languages; the allowlist stays the policy surface either way.
** DECISION (2026-06-19) Wasm is the sandboxed exec tier (C1c)
Context: C1a made eval default-deny and C1b bounded the process-spawn
backends, but a trusted shell/python block still runs with full host
access (filesystem, network, exec). C1c needed a tier with no host
surface at all. Options: (a) seccomp/landlock-jail the spawned
interpreters (linux-only, fiddly, needs unsafe/privileged syscalls vs
=#![forbid(unsafe_code)]=); (b) run wasm modules under wasmtime with an
empty import set. Taken (b): reuses the W1-W4 wasmtime integration
pattern (safe API only, feature-gated), gives true containment (no
imports => no host calls; fuel budget => no infinite loop), and is
cross-platform + hermetic-testable. Layering: closure-eval (Layer 3)
must not depend on closure-plugin-host (Layer 4), so it carries its own
small =WasmBackend= rather than reusing =WasmRuntime= — minor
duplication, recorded. Trade-off: only languages that compile to wasm
get the sandbox; shell/python remain the opt-in "trusted" tier under
C1b bounds. Reversible: an OS-jail backend can be added later as
another tier behind the same =eval_trust= allowlist.
** DECISION (2026-06-19) CRDT ships block-level LWW; char-level CRDT deferred
Context: spec.md:160 promised "wraps Document with Automerge or Yrs,"
but =closure-crdt= ships hand-rolled per-block per-field (title, body)
last-writer-wins registers + vector clocks. The spec and code diverged
(the C2 gap). Options: (a) adopt Automerge/Yrs now; (b) keep LWW, fix
the spec to tell the truth, queue the real text CRDT as C2b.
Taken (b): Automerge 0.5 / Yrs each drag a large transitive-dep tree
(and Yrs leans on async stacks), which fights I10's hermetic dep-minimal
build — the same reason iroh was passed over in the 2026-06-17 P2P
Decision. The shipped LWW model is genuinely convergent, commutative,
and idempotent at the block/field grain (tested: merge.rs, conflicts.rs,
session.rs), which covers concurrent edits to *different* blocks/fields
— the common case. The honest limitation: two peers editing the SAME
field concurrently merge LWW, so one side's characters are dropped (no
char-level interleave). spec.md:160 now states this outright.
Reversible: C2b adds a char-level body CRDT (Automerge / Yrs / a minimal
hand-rolled RGA evaluated against I10) behind the SAME =Edit=/=BlockId=
surface, so closure-core, shells, and parsers do not change
(spec.md:218 readiness note). Recorded with no code change — this entry
+ the spec edit are the whole of C2a.
** DECISION (2026-06-17) P2P transport: std TCP now, iroh/QUIC later
Context: S4 called for an iroh transport behind =--features iroh=, with
the live network transfer as a manually-checkable (untestable) part.
Options: (a) pull iroh 1.0 — async QUIC, tokio, rustls, ~200 transitive
crates — and write send/recv I cannot hermetically test; (b) a std
=TcpStream= transport over loopback, zero new deps, fully testable.
Chose (b): =TcpSyncTransport= ships the =SyncMessage= bytes over real
sockets and is verified end-to-end over =127.0.0.1= in =just check= (no
DROP, no faked network assertion), keeping the default build light and
hermetic (I10). The wire is the transport-agnostic =SyncMessage=
protocol, so iroh/QUIC (NAT traversal, dialing by public key) is a
drop-in replacement behind the same frames when a network test harness
exists — reversible. Trade-off: no real NAT-punching P2P yet (LAN/relay
TCP only).

** org2 decision: track upstream org-mode as compatibility target; org2 export-only (2026-06-13)
Context: org-mode (Emacs) is the de-facto plain-text PKM format with
decades of files, tooling, and users. The parser scope (spec.md) and
all golden roundtrips (I1) target a practical subset of current upstream
org (headlines+TODO+tags+drawers+babel blocks+lists+timestamps+links+...).
Options considered: (a) track Emacs org git master as "the" target and
only add constructs when they land upstream + we can roundtrip them

this project and make the parser accept both; (c) treat org2 as a
separate future format.

parse target. Rationale: chasing an in-flight org2 would violate I1

+ fuzz + #![forbid(unsafe)] stays tractable only for a bounded subset),

complex conditionals hurt), and the "built to last" primitives (parse
stays simple + span-preserving). Existing org files and workflows keep
working; richer export paths can be added without perturbing the kernel
or forcing users to migrate. Reversible: later add an org2 feature
crate or export mode (behind cfg or CLI flag) that consumes the same
Document IR and emits the new syntax; the core parser contract and
vault stay on upstream-org-compat. Recorded after full project review
of parser, fixtures, invariants, and prior md-compat decision.
